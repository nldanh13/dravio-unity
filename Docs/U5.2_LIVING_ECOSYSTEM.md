# U5.2 — Living Ecosystem integration candidate

Base: U5 Schema v8, Rig v3. This is a ground-only Origin vertical slice, not a completed behavior system.

## Runtime
- One GameSession; the bridge reads canonical State and sends canonical commands. No save/schema, Domain, Character Runtime or environment rules are changed.
- When a local DragonVisualCatalog with an Emberling prefab exists, the legacy visual controller is disabled before Start and its renderers/lights/colliders are hidden. If the catalog is missing, legacy preview stays usable. Import the catalog before regenerating the scene.
- UID-keyed SanctuaryDragonSync drives models, stage swaps, spawn/despawn/pooling. Only idle residents in Origin with the canonical Walk capability, a catalog prefab and a safe spawn are rendered. No substitute species. Catalog stage fallback is reported in profile. Missing/unsupported residents remain selectable through the roster.
- Ground movement is visual-only, with existing safe point/segment checks and spacing; no navmesh, aquatic/flying movement, AI1 behavior intents or social simulation yet.
- Tap/click model bounds or use Next dragon. Inspect follows selected model; Resume restores camera. Selected profile includes UID, stage, mutation, personality, location, suitability and catalog match. Observe records the existing species profile. Habitat/storage actions use Ecosystem eligibility and GameSession.
- Feed chooses the first canonical diet, displays a temporary marker near selected dragon and consumes via a separate command. It never transfers the pending food to another selected UID. Marker is a generic placeholder; pending food restored after reload is not reattached by this slice and expires in Domain. Sleep is explicitly visual-only.
- New scene OriginLivingEcosystem, prior generated scene paths preserved. Shared generated environment assets and save directory still require backups.
- Existing management/health UI stays independent; no departure button until visual and local verification.

## Local acceptance (not executed remotely)
1. Back up saves/local assets, import real character manifest, regenerate with Dravio > Open Game.
2. Verify no catalog: legacy preview and buttons. With catalog: exactly one visual per eligible UID; no legacy duplicate.
3. Hatch/claim second resident, select both by touch/roster, pet and feed each, inspect and resume. Touch over HUD must not select a model. Check cooldown and wrong placement errors.
4. Move to storage and back; move to another unlocked Origin habitat; full/locked/unsuitable destinations are blocked by Domain. Reload; stage progression and model changes use true UID; missing models do not replace with Emberling.
5. Verify care/shelter/breeding/expedition residents are hidden, stage fallback visible in profile, no new rewards or save mutations from visual-only wandering/sleep.
6. Test 5/15/30 real characters, Unity Console, FPS, memory, safe-area and landscape touch. Unity editor compilation and PlayMode remain mandatory.
