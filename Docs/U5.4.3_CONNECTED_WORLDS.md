## Architecture
OriginConnectedWorlds.unity remains loaded as the shell for the existing DravioSessionHost, one GameSession, one clock/command bus/file lock, overlay HUD and visual pool. Origin environment roots are captured at scene generation, excluding the legacy dragon and EventSystem. For Ocean/Sky, suspend visual presentation and adapter commands, release interaction reservations, stop follow/trace, clear visual food marker and despawn projected models; disable origin environment roots preserving their activeSelf. Additively load exactly one environment-only scene (not a second game scene), verify expected zone metadata and one active environment/orthographic camera, set active scene and restore the previous displayed hour. Bind the same controller/manager to that location data/camera. Unload previous remote scene before another load; failed validation attempts return to Origin, disable further loads on unload/restore failure. A duplicate DravioSessionHost now fails closed in Awake before any new GameSession is created. The original host remains loaded; switching does not invoke lifecycle hide/show or migration.

The UI visits worlds only if canonical zone unlocked and scene registered. Visiting is read-only; dragons are never moved or copied by scene load. The existing Dragons roster still cycles through all non-released UIDs, shows current canonical location and separately allows choosing a canonical TravelOption (zone + habitat), including blocked reason; MoveDragonCommand is the only transfer path, checked again by Domain. Existing ground-capable residents are shown only in current unlocked zone/habitat with valid ground spawn. Storage/care/shelter/breeding/expedition/released or other-world residents never get projected there. Swim-only/air-only and no-safe-ground models are not shown, with explicit status. No automatic cross-medium animation, no new spawn geometry, no live transitions. On return positions are rebuilt from authored spawns, not persisted frame coordinates. Any local food marker is cleared when switching; corresponding canonical drop remains subject to existing expiry (no refund/auto-consume). No new schema or Domain rules. Original guide/egg claim buttons still refer to Origin, clearly labeled; roster movement is general.
